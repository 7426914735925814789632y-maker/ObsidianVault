意味: 同スプシの「送信待ち」行を検知し、QRカード画像生成・X API v2への4枚画像付き自動投稿・GitHub ActionsへのObsidianページ生成指示を一括実行するGASシステム

## 概要・トリガー
- **呼び出しワード / 発火条件:** スプレッドシート `UZU_X投稿連携`（`シート1`）の変更時トリガー（`sendPendingPosts`）／ Webアプリ `doGet(e)`（X OAuth 2.0 PKCE認証コールバック用）
- **対象 / 連携先:** [UZU_X投稿連携](https://docs.google.com/spreadsheets/d/1hwVCfXIkZxHKRp-bIa9CVzZUSZbjNs36ZbM9TeyTXKY/edit)、Googleスライド＆ドライブ（`uzu_logo.png`）、X API v2（課金元 `@number012_fosch` / 投稿先 `@hia_fosch`）、GitHub API（`7426914735925814789632y-maker/ObsidianVault` の `repository_dispatch`）
- **動作:** `F列 === "送信待ち"` の行を読み取り、卓URLからタイトル・サムネイルを取得して「QR＋UZUロゴ＋タイトル」カードをGoogleスライド経由でPNG化し、Xへ画像4枚（①サムネイル→②キャラ画像→③成績スクショ→④QRカード）付きで投稿後、GitHub Actions（`create-uzu-page`）を発火させる

## AIが陥りやすい罠・必須の制約事項（仕様の勘所）

「本文にURLを直書きするな、QR画像に逃がして20セント課金を回避せよ」
1. **X API v2のURL課金回避と本文整形＝**
  - X API v2の従量課金では投稿本文にURLを含めると1回 `$0.20` かかるが、URLなしの投稿は `$0.015` で済む。また前後に定型ハッシュタグを自動付与するため文字数上限（全角140字）に引っかかりやすい。
  - **対策:** C列の本文から卓URLを抽出・除去してQRコード画像化し、4枚目の添付画像として投稿する。本文は `【#マーダーミステリー】\n\n『タイトル』\n\n{感想文}\n\n#UZU #マダミス` の順に整形する。

「X投稿に成功したら、GitHubがコケる前に即F列を『送信済み』にしろ」
2. **二重投稿の防止とループ停止の回避＝**
  - X投稿成功後のGitHub API呼び出し等でエラーが発生した場合、F列が `送信待ち` のままだと次回実行時にXへ二重投稿されてしまう。また1行の例外でループが止まると後続の `送信待ち` 行がすべて詰まる。
  - **対策:** `POST /2/tweets` 成功直後に即座にF列を `送信済み` に更新し、GitHub連携の成否は別列のL列（`連携済み` / `エラー`）へ記録する。さらに各行の処理を `try / catch` で囲み、失敗時はF列に `エラー: ...` を書いて次の行へ進む。

「スライド生成は即ゴミ箱へ、タイトルと説明文の座標は広めに離せ」
3. **QRカード画像の生成レイアウトと一時ファイル掃除＝**
  - GAS単体では日本語テキスト入りの合成画像を作れないためGoogleスライドを経由するが、長いシナリオタイトルが2行になると下の説明文と文字被りし、また一時ファイルがドライブに溜まる。
  - **対策:** `SlidesApp.create` で一時スライドを作成し、タイトル枠（18pt・高さ80）と説明文枠（`y=338`）を十分に離して配置したうえでPNG書き出しし、直後に `setTrashed(true)` でゴミ箱へ移動する。

「外部APIからの追記は『変更時トリガー』がスルーすることがある」
4. **スプレッドシート変更時トリガーの未発火＝**
  - ブラウザ上でセルを手編集したときは即座に動くが、Gemini等の外部API経由でシートに行を追加した場合は「変更時」トリガーが反応しないケースがある。
  - **対策:** 追加後に反応しない場合はApps Scriptから `sendPendingPosts` を手動実行するか、時間主導型トリガー（5〜10分おき）を併用する。

「トークンや鍵はコードに直書きせず『スクリプトプロパティ』で回せ」
5. **認証トークンとGitHub PATの安全な管理＝**
  - XのOAuth 2.0アクセストークンは2時間で失効するためリフレッシュトークンでの自動更新が必須。また `GITHUB_TOKEN` をコードに直書きすると漏洩リスクがある。
  - **対策:** `REFRESH_TOKEN_<username>` を `PropertiesService` に保存して `getFreshAccessToken` で毎回更新し、`GITHUB_TOKEN`・`GITHUB_OWNER`・`GITHUB_REPO` もすべてスクリプトプロパティに格納する。
