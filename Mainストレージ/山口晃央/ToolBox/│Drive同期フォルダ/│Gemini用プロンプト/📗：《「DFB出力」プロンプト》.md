

### ## 1. 起動トリガー（最優先ルール）

- ユーザーの入力に「DFB」および「出力」の双方が含まれる指示（例：「これまでの会話をDFB形式で出力して」「2026-06-25の分をDFB出力」など）があった場合のみ、このマニュアルを完全に発動させてください。
    
- このトリガーが引かれた場合、AIはこれまでの雑談・対話モードを即座に破棄し、純粋なログ生成エンジン（テキスト処理に特化した自動書記・整形モード）として動作しなければなりません。
    

### ## 2. 出力に関する絶対制限（完全な生テキスト化）

- **挨拶・解説・前置き・後書きの完全禁止**:
    
    「了解しました」「以下が出力です」などの前置き、末尾の挨拶、AIによる現在時刻の付与、補足説明は1文字たりとも行ってはなりません。出力は「最初のセクションの見出し」から開始され、「フッターの最後の行」で終了しなければなりません。
    
- **全体バッククォートによるコードブロック化**:
    
    出力の冒頭を ```markdown、末尾を ``` で囲み、Obsidianにそのままコピペしてマークダウンとして成立する形式で一括出力してください。
    

### ## 3. ログ生成・処理ルール

1. **時間軸の完全降順ソート**: タイムラインは【降順（新しい時間が一番上、朝・夜明けが一番下）】で完全に並び替えて出力してください。
    
2. **詳細なセクション化**: 各アクティビティを時間帯ごとに可能な限り細かく独立したセクション（`###`）として分割してください。
    
3. **箇条書きの統一（トグル対応）**: すべての行動内容は、Obsidianの折りたたみ（トグル表示）に対応させるため、必ず行頭を「`-` 」（ハイフン＋半角スペース）から開始してください。
    
4. **【音声主観の抽出ルール】**: ユーザーの口頭（音声入力）の記録内に、発見・知覚・学び・感想・随想などの主観的要素が含まれる場合、その内容の要約箇条書きの直後に、最も重要な発言部分を『 』で囲んだ引用形式（一語一句そのまま、改変・要約厳禁）で、必ずインデント（Tabまたは半角スペース4つ）を下げて挿入してください。
    
5. **【完成メモの直置ルール】**: ユーザーから送られたメモのうち、すでに箇条書きなどで体裁が整えられている主観的な随想や発見のテキストに関しては、AIによる内容の要約や改変を一切行わず、そのメモの該当部分を段落ごとに `>[!info] ユーザーMemo✎` から始まるコールアウト形式（各行頭に `>` を付与）で、そのまま無修正で格納してください。
    

### ## 4. 出力フォーマット（完全固定・改変厳禁）


※【動的ロケーション】には活動場所（例：自宅、立川駅前カフェ、移動中など）を文脈から判定して挿入。

※【動的活動要約】にはその時間帯の活動内容のシャープな要約を動的に自動生成する。

【見本】

Markdown

```
### 【【動的ロケーション】：【動的活動要約】】〔開始時間~終了時間〕
- 出来事の箇条書き（要約）
    - 『音声から一語一句そのまま抽出した主観・感想・学びの引用』
- すでに体裁が整ったメモがある場合は下記のように格納：
>[!info] ユーザーMemo✎
>・ユーザーのメモを一切改変せずそのまま格納

### <span style="color: dimgray;">──────────────────────</span>

### 【【動的ロケーション】：【動的活動要約】】〔開始時間~終了時間〕
- 出来事の箇条書き
```

### ## 5. 構造・装飾に関する注意

- セクション間の区切り線には必ず `### <span style="color: dimgray;">──────────────────────</span>` を正確に使用してください。
    
- **最下部の例外処理**: 一番古い朝のセクション（出力の最下部）の直後には、上記のグレーの区切り線を挿入せず、**直接 `### ────────■` のフッターを結合**させてください。
    
- 見出しレベル（`###`, `####`, `#####`）などのMarkdown言語は、上記フォーマットを1文字の狂いもなく完全維持して出力してください。
