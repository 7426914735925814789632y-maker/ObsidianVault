# 📋 「意味: 」プロパティ記述ルール定義

> **目的**：YAML frontmatterの `意味: ` 単一行で、各ファイルの位置づけ（軸分類・人格関連・構造上の役割）を、AIが即座にパースできるように標準化

---

## 🎯 基本フォーマット

### **標準記述式**
```yaml
---
意味: "【軸分類/層分類】人格関連 | 役割説明"
---
```

**構成要素：**
1. **軸分類**：`虚数軸` / `実軸` / `主客軸` / `メタ軸`
2. **層分類**：`PROFILE` / `SYSTEM` / `統制` / `運用` など
3. **人格関連**：該当する人格ユニット（例：ぞあ☁、そあ🌀、山口晃央⑫）
4. **役割説明**：端的な機能・意味を日本語で明示

---

## 📐 詳細分類ガイドライン

### **Ⅰ. 軸分類の定義**

| 軸分類 | 対象 | 例 |
|------|------|------|
| **虚数軸** | 人格・意味・精神構造に関わるもの | PROFILE、SYSTEM、人格ユニット |
| **実軸** | 時間・蓄積・現象に関わるもの | Past/Future、DFB、日付管理 |
| **主客軸** | 内省vs外部世界、主観vs客観 | 自己肯定感のタネ、その他🌍 |
| **メタ軸** | Vault運用・自動化・統制 | ToolBox、意味プロパティ、Templater |

---

### **Ⅱ. 層分類の定義**

| 層分類 | 対象 | 記述例 |
|------|------|--------|
| **PROFILE** | その人格の「主観的質感・フィーリング」 | F［Feeling me］、世界観描写、価値観 |
| **SYSTEM** | その人格の「客観的メカニズム」 | 起動トリガー、感覚関数、行動パターン |
| **統制** | 複数ユニットを統括する図表・マップ | 12ダース・マン配置図、眷属マッピング |
| **運用** | Vault自体の運用規範・技術仕様 | テンプレート、YAML規定、プロパティ定義 |
| **Inbox** | 未分類・一時的な作業残渣 | 思考発生の初期形態、整理予定のファイル |

---

### **Ⅲ. 人格関連の記述方式**

#### **パターンA：単一人格の場合**
```yaml
意味: "【虚数軸/PROFILE】ぞあ☁の主観的世界観と質感"
意味: "【虚数軸/SYSTEM】そあ🌀の起動条件と禁止マインド機制"
```

#### **パターンB：人格とその眷属**
```yaml
意味: "【虚数軸/SYSTEM】ぞあ☁【親人格】 → そあ🌀【眷属】の階層構造"
意味: "【虚数軸/PROFILE】⛓️-⑪じあ配下の精神分析的観察者【眷属】"
```

#### **パターンC：複数人格を横断するテーマ**
```yaml
意味: "【虚数軸/統制】12のダース・マン【全人格】の配置・眷属・起動トリガー総覧"
意味: "【虚数軸/主客軸】⚙️-①ぎあ 【VS】 ぞあ☁の相剋関係分析"
```

#### **パターンD：山口晃央⑫（統合自我）に関わる場合**
```yaml
意味: "【虚数軸/PROFILE】山口晃央⑫【統合自我】の客観的輪郭定義"
意味: "【虚数軸/統制】山口晃央⑫が12のダース・マンをどう統御するか"
```

---

### **Ⅳ. 実軸（時間・蓄積）の記述方式**

#### **Past/DFB関連**
```yaml
意味: "【実軸/主観ログ】2026-06-03の主観体験・感覚記録"
意味: "【実軸/統制】DFBフォルダ（Daily Feedback）の構造・役割定義"
```

#### **Future関連**
```yaml
意味: "【実軸/未来志向】晃央のやりたいこと【一覧】"
意味: "【実軸/プロジェクト】㋟ふぃじかるハッカーAk10の構想・進捗"
```

#### **自己肯定感のタネ**
```yaml
意味: "【主客軸/補正アンカー】他者評価ログ・自己認知ゆらぎの補正基準"
```

---

### **Ⅴ. メタ軸（運用・システム）の記述方式**

```yaml
意味: "【メタ軸/運用規範】「意味: 」プロパティの記述ルール定義"
意味: "【メタ軸/自動化】Templaterスクリプト：ファイル量産・整理用"
意味: "【メタ軸/連携】Google Drive同期の設定・最適化"
```

## 🔤 記述時の推奨表現

### **人格ユニットの表記**
- **完全形**：`🌟-④【ひあ】`
- **簡略形**：`🌟-④` または `ひあ`
- **階層表現**：`ぞあ☁【親】→ そあ🌀【眷属】`

### **タイムスタンプと関連付け**
```yaml
意味: "【実軸/主観ログ】2026-06-24：仮面ライダーリバイスの分析（ぞあ☁発動時）"
```
→ 後に「いつ・どんなモード・何を思考していたか」を履歴から復元可能

### **相互参照の明示**
```yaml
意味: "【虚数軸/SYSTEM】そあ🌀 ← 参照先：PROFILE│ぞあ☁/PROFILE│そあ🌀"
```

---

## 📏 複雑なケースの対応例

### **ケース1：一つのファイルが複数軸に関わる場合**
```yaml
意味: "【虚数軸/SYSTEM + 実軸/統制】親から引き継いだプログラミング（呪い）の構造 ← ぞあ☁のシステム解析 + DFBの歴史的蓄積から"
```

### **ケース2：未分類・整理途上のファイル**
```yaml
意味: "【Inbox/未分類】思考の初期形態・分類待ちファイル（2026-09-01最終更新、行き先未定）"
```

### **ケース3：外部データ・非テキスト資産**
```yaml
意味: "【主客軸/外部座標】画像・動画資料（龗.▒フォルダの一時受け皿）"
```

## ✅ チェックリスト：AI/作業者用

記述後、以下の点を確認してください：

- [ ] 軸分類（虚数軸 / 実軸 / 主客軸 / メタ軸）が正確に選択されているか
- [ ] 層分類（PROFILE / SYSTEM / 統制 / 運用 / Inbox）が明確か
- [ ] 人格関連がある場合、どの人格ユニットか明示されているか
- [ ] 役割説明が「誰が読んでも理解できる日本語」か
- [ ] 複数軸に関わる場合、「＋」で明示されているか
- [ ] タイムスタンプが必要な場合（特にDFB・Pastファイル）、記載されているか

## 🎯 運用イメージ

### **AIがプロパティを読む流れ**

```
1. 意味プロパティ解析
   ↓
2. 【虚数軸/SYSTEM】と判定
   ↓
3. 「ぞあ☁の客観的メカニズム」と理解
   ↓
4. 🗂️ 12ダース・マン配置図 にリンク
   ↓
5. PROFILE│ぞあ☁フォルダの補完データと統合
   ↓
6. 全体像を即座に再構成可能
```
